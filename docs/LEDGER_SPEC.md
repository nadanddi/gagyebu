# 가계부 데이터 구조와 가져오기 원칙

## 목적

은행 및 결제수단별 거래내역을 하나의 원장으로 합치고, 실제 소비와 계좌 이동을 구분합니다.
최신 통합 가계부는 출금과 입금을 분리합니다. 지출 합계는 지출성 출금만 반영하고, 환급은 입금 쪽에서 별도로 기록합니다. 본인 계좌 간 이동은 지출과 외부입금 합계에서 제외합니다.

## 이전 토스 예시 구조 (보존)

- `월간요약`: 순소비액, 소비/환불 건수, 분류대기 수, 항목별 및 일자별 합계
- `거래원장`: 원본 거래를 정규화한 전체 내역과 최종 소비 분류
- `분류대기`: 상호만으로 용도를 알기 어려운 거래의 확정분류 입력
- `설정`: 분류 목록, 원본 기간, 소비 제외 및 환불 처리 원칙

## 거래원장 핵심 열

| 열 | 설명 |
| --- | --- |
| 거래ID | 원본과 행을 연결하는 고유 식별자 |
| 날짜/시간 | 거래 승인 또는 발생 시점 |
| 출금/기록은행 | 거래내역서를 제공한 은행 |
| 결제방식 | 체크카드, 계좌이체/간편결제, 해외카드 등 |
| 적요 | 가맹점 또는 거래 설명 |
| 원거래금액 | 거래내역서의 부호를 보존한 금액 |
| 소비금액 | 소비는 양수, 환불은 음수, 제외 거래는 0 |
| 자동분류 | 규칙이 제안한 소비항목 |
| 최종분류 | 분류대기에서 사용자가 확정한 결과 |
| 집계구분 | 소비, 환불, 내부이체, 입금, 조정 |
| 분류상태 | 완료 또는 확인필요 |

## 2026년 8월 토스뱅크 처리 원칙

- 체크카드 출금은 소비로 집계합니다.
- 체크카드 입금성 거래는 환불로 보고 소비금액을 음수로 반영합니다.
- 본인 이름으로 오간 이체와 카드잔액 자동충전은 내부이체로 분류해 소비에서 제외합니다.
- 캐시백, 이자, ATM 입금은 소비에서 제외합니다.
- 카카오페이처럼 실제 사용처가 보이지 않는 거래는 `기타`와 `확인필요`로 둡니다.
- 결과 파일에는 상대 계좌번호 마지막 네 자리만 남깁니다.

## 다음 가져오기에서 필요한 규칙

- 은행별 열 이름과 금액 부호를 공통 스키마로 변환
- 동일 거래가 은행과 결제서비스 양쪽에 나타날 때 중복 제거
- 본인 계좌 목록을 이용한 내부이체 매칭
- 지역상품권 충전과 실제 결제를 구분
- 네이버페이 충전, QR 결제, 환불을 구분
- 사용자가 확정한 상호-분류 규칙을 다음 달 자동분류에 재사용

## 개인정보 처리

이 GitHub 저장소에는 거래 원문, 계좌번호, 개인 Google Drive 링크와 생성된 가계부 파일을 저장하지 않습니다.
실제 데이터와 결과 시트는 사용자의 Google Drive에서 관리합니다.

## 최신 통합 구조와 확정 기준

- 월간요약: 지출, 외부입금, 전체 출금·입금, 일별·분류별·기록계좌별 합계.
- 출금관리: 모든 출금과 내부이체를 기록하고 지출집계액을 별도 수식으로 계산합니다.
- 입금관리: 모든 입금을 기록하고 내부이체를 제외한 외부입금액을 계산합니다. 외부입금을 모두 소득이라고 판단하지 않습니다.
- 원본대조: 원본 부호금액, 잔액, 출처와 행 식별자를 보존합니다.
- 내부이체 및 카드잔액 자동충전은 제외하며 거래 행은 삭제하지 않습니다.
- 상품권은 충전한 날짜에 실제 은행 출금액을 지출로 기록합니다. 이후 상품권 사용내역을 가져올 때 이중 집계하지 않습니다.
- 타인송금은 지출로 기록합니다. 용도 미확인 송금은 기타·확인필요에 둡니다.
- 간편결제는 은행 내역에 가맹점이 없으면 용도를 추측하지 않습니다.
- 기준 날짜는 은행에 기록된 대상 월의 거래일이며, 이전 달 이용분도 대상 월 출금이면 포함합니다.
- 기록은행은 명세서를 제공한 계좌입니다. 다른 계좌에서 충전한 자금의 최종 원천을 확정한 값은 아닙니다.
- 분류·메모는 관리 원장의 동일 행에서 수정합니다. 행 전체를 표 기준으로 정렬해 거래ID와 입력을 함께 보존합니다.
- 원본에 입금유형과 금액 부호가 충돌하면 유형 기준 표시값과 원본 부호금액을 분리하고 확인 대상으로 남깁니다.
- 합계 수식은 이번 가져오기 범위 기준입니다. 새 거래를 추가하는 반복 가져오기는 별도 검증이 필요합니다.
